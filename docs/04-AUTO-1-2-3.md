# AUTO 1, AUTO 2 i AUTO 3

Poziom autonomii wyznacza najdalszy dozwolony etap pipeline. Nie zmienia kryteriów jakości ani blokady push.

| Funkcja | AUTO 1 | AUTO 2 | AUTO 3 |
|---|:---:|:---:|:---:|
| analiza i routing | ✓ | ✓ | ✓ |
| research, gdy wymagany | ✓ | ✓ | ✓ |
| plan, ETA, ryzyka, acceptance criteria | ✓ | ✓ | ✓ |
| zmiany plików | — | ✓ | ✓ |
| właściwe testy i diff | — | ✓ | ✓ |
| postcondition validation | plan | ✓ | ✓ |
| retry i eskalacja | — | ✓ | ✓ |
| lokalny commit | — | — | dozwolony |
| push | zablokowany | zablokowany | zablokowany |

## AUTO 1

AUTO 1 służy do bezpiecznej analizy. Zwraca routing, potrzebę i powód researchu, złożoność, ETA MIN/TYPICAL/MAX, plan, ryzyka, kryteria akceptacji oraz oczekiwany zakres plików i testów. Nie uruchamia implementacji i musi zakończyć się z zerową liczbą zmian.

## AUTO 2

AUTO 2 wykonuje implementację w sandboxie, uruchamia właściwe testy, zapisuje diff i waliduje kryteria. Kod wyjścia executora nie wystarcza do sukcesu. Jeżeli zadanie wymaga zmiany, a diff jest pusty, wynik nie może być `completed`. Automatyczny commit jest niedozwolony.

## AUTO 3

AUTO 3 wykonuje pełny pipeline. Może stosować retry, eskalować LOCAL do CODEX i po udanych testach utworzyć lokalny commit. Zawsze zatrzymuje się przed push. Uprawnienie do commita nie jest uprawnieniem do publikacji.

## Dry-run a AUTO 1

Dry-run wymusza brak modyfikacji niezależnie od poziomu wybranego w UI. Najczytelniejszym połączeniem planistycznym jest AUTO 1 + Dry-run.
